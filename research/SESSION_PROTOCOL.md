# Lightweight session and integrity protocol

User instructions take precedence; a pasted named session prompt is authority to **run that session**, never to start later sessions automatically. No separate permission gate, artificial stop/strike, mandatory audit interval, or RL conveyor mechanics. The old documents under legacy/ are history, not binding instructions.

Read THEOREM_TARGET, PROOF_LEDGER, OPEN_GAPS, and the latest DG session first. Consult original frozen artefacts only when a specific mathematical dependency warrants it.

Each session should:
- state one or several falsifiable propositions whose **exact** implication for E is written;
- spend substantive effort proving and attacking them (counterexamples first where promising);
- state definitions, assumptions, ranges, and finite vs universal quantifiers;
- record proved analytic facts, external claims, finite certificates, experiments, conjectures and killed routes separately;
- update proof and gap ledgers when something actually changes;
- record precise files, source versions and commands for each external/finite check; don't claim a test ran if it did not;
- give a usable next-session task, but no automatic execution.

Maintain a single compact active ledger and a correction trail in Git history. Never upgrade a theorem because a session ran, a script exited cleanly, or a proof was described as promising. Use direct readable file links in closeouts.
